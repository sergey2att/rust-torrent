# RustTorrent

[English](README.en.md) · Русский

**Полноценный BitTorrent-клиент на Rust с нуля — от bencode-парсера до собственного GUI.**

Скачивает **и раздаёт** торренты по `.torrent`-файлу или magnet-ссылке: трекеры (HTTP + UDP),
Kademlia DHT, peer exchange, UPnP, параллельная докачка с 50 пирами, многоторрентный движок
и тёмный нативный UI на Tauri.

## Возможности

- **Скачивание и раздача** — полный жизненный цикл: recheck → докачка → seeding до выключения
- **Все источники пиров**: HTTP/UDP-трекеры (BEP 3/15), DHT-рой (BEP 5), ut_pex-обмен пирами (BEP 11)
- **Magnet-ссылки** — метаданные собираются у пиров через ut_metadata (BEP 9) с fail-closed
  проверкой SHA-1; работает без трекеров, по чистому DHT
- **Многоторрентный движок** — один порт на процесс, accept-роутер по info_hash, общий DHT,
  пауза/резюм in-place без recheck, персистентность списка и routing table DHT между запусками
- **Скорость и живучесть сворма**: rarest-first с тай-брейком, pipeline 5 блоков, endgame,
  параллельный recheck на все ядра (rayon), choking round-robin + optimistic-слот,
  вытеснение бесполезных сидов из полного пула, UPnP-проброс порта с анонсом внешнего порта
- **macOS UI**: Tauri v2 + Svelte 5, тёмная тема, таблица торрентов, прогресс по кускам как в
  Transmission, drag-and-drop, magnet-вставка, системные уведомления; закрытие окна оставляет
  раздачу в фоне, выход через Cmd+Q — чистый teardown (анонсы `Stopped`, NAT unmap)

## Что было интересно

- **Протокол реализован руками, а не из библиотеки.** Свой bencode-кодек со строгой канонической
  формой, info-hash по сырым байтам словаря `info` (никогда не пересериализуется), handshake
  68 байт, фрейминг BEP 3, полный Kademlia-Responder, UDP-announce с ретраями по спецификации.
  Вся сетевая машина — на tokio, архитектура — актор на mpsc (хаб / peer-задачи / задача-писатель
  диска), в `select!` гоняются только cancel-safe `recv()`.
- **Минимальные зависимости.** Никаких serde/serde_bencode/byteorder для протокола; workspace из
  11 крейтов «один крейт — одна ответственность», библиотечные крейты — без `unsafe` и без
  `unwrap`/`expect` (enforced линтами), типизированные ошибки через `thiserror`.
- **Инженерная культура вместо «написал и забыл»**: детальные юнит-тесты на каждый вариант ошибки
  (обрыв ввода на каждом суффиксе, мусор после валидных данных, DoS-кейсы), интеграционные тесты
  с фейковыми пирами, приёмка на живом сворме, и обязательная проверка «тесты ловят баги» —
  намеренная поломка кода должна ронять тесты.
- **Проверено в бою**: Debian 13.6 netinst (755 МБ) качается и по `.torrent` через трекеры, и по
  magnet без единого трекера (чистый DHT) — в обоих случаях SHA-256 совпадает с официальным.
  В изолированном сворме из двух инстансов сидер отдаёт весь торрент целиком.

## Про проект: человек + AI-агенты

RustTorrent — **обучающий проект по работе с AI-агентами**: весь код написан в паре с LLM-агентами
(claude-code / pi), по этапному плану, где человек выступает архитектором и ревьюером.

Методология:

1. **Каждый этап начинается с «прожарки» (grill)** — агент-интервьюер стресс-тестирует план:
   развилки дизайна фиксируются явными решениями до первой строки кода
2. **Все решения — в `AGENTS.md`** — единый контекст для агентов: архитектура, константы,
   «не менять без обсуждения», ловушки, найденные на практике (bounded mpsc, cancel-safe select,
   one-shot bitfield, offset-66…)
3. **Definition of Done, enforced машинно** — clippy `-D warnings`, fmt, тесты; код без тестов
   равен коду, которого нет; при фиксе бага — сначала падающий тест
4. Итог: 8 этапов от bencode-парсера до GUI-приложения — и документированная история решений,
   по которой агенты (и люди) могут проследить, почему система устроена именно так

## Сборка и запуск

```bash
cargo build --release
cargo run --release -- <file.torrent | magnet:?> <download_dir> [port] [--no-seed]
cargo test                                             # офлайн-тесты
cargo test -p cli -- --ignored                         # ручной smoke: реальные трекеры, DHT, magnet

# UI-приложение (macOS):
cd app && npm install && npm run tauri dev
```

Пример magnet-скачивания (кавычки обязательны — в URL есть `&`):

```bash
cargo run --release -- "magnet:?xt=urn:btih:<40-hex>&tr=<announce-url>" ~/Downloads
```

## Как это устроено (cargo workspace)

| Крейт          | Ответственность                                                                             |
|----------------|---------------------------------------------------------------------------------------------|
| `bencode`      | кодек bencode: потоковый decode, строгая каноническая форма, лимит глубины                  |
| `metainfo`     | разбор `.torrent` (BEP 3 + BEP 12), magnet-ссылки, info-hash                                |
| `tracker`      | HTTP и UDP (BEP 15) announce: компактные пиры + фолбэк на список словарей                   |
| `peer-wire`    | handshake 68 байт, фрейминг BEP 3 (включая Extended BEP 10), `Bitfield` с валидацией        |
| `ext-pex`      | ut_pex (BEP 11): кодек дельт пиров, кап 1000, строгий парсер                                |
| `nat`          | UPnP IGD-проброс TCP-порта (igd-next), блокирующий крейт за `spawn_blocking`                |
| `dht`          | Kademlia DHT (BEP 5): полные k-buckets, итеративный обход, responder, `find_peers` → Stream |
| `ext-metadata` | ut_metadata (BEP 9): сборка метаданных с SHA-1-проверкой, отдача чужим пирам                |
| `engine`       | сессия: скачивание + раздача + magnet-фаза; rarest-first, endgame, choking, актор на mpsc   |
| `daemon`       | многоторрентный оркестратор: реестр, accept-роутер по info_hash, общий DHT, статусы для UI  |
| `cli`          | сквозная проверка: `.torrent` или magnet, скачивание + раздача до Ctrl+C                    |
| `app/`         | Tauri v2 UI (Svelte 5): таблица торрентов, Transmission-бар кусков, тёмная тема             |
